============================================================
이 프로그램의 용도
============================================================
Ultra Random Prompt는 이미지 생성 모델에 입력할 영어 프롬프트 문구를 조합·편집·관리하는 단일 HTML 도구입니다.
메인 「생성하기」는 이미지를 생성하는 버튼이 아니라 영어 프롬프트 텍스트를 생성하는 버튼입니다.
ComfyUI를 포함한 여러 워크플로에서 사용할 수 있도록 자연어형과 태그형을 제공합니다.

별도 창으로 여는 「이미지 분석」은 업로드한 이미지에서 영어 프롬프트를 추출합니다(OpenAI/Gemini/Ollama Vision).
선택 사항인 「AI 이미지 미리보기」는 OpenAI/Gemini API를 사용해 이미지를 요청하며 별도 비용이 발생할 수 있습니다.

KO/EN 화면 전환은 메뉴·도움말·상태 안내의 언어만 바꿉니다. 생성되는 프롬프트와 사용자가 입력한 원문은 그대로 유지됩니다.
성인 NSFW 카테고리는 프롬프트 텍스트용 선택 기능입니다. 성인 대상 사용을 전제로 하며 화면 언어에 따라 내용을 제한하지 않습니다.

API 키를 HTML 안에 직접 넣은 파일은 공유하지 마십시오. 공용 기기에서 API 키를 저장하지 않는 것이 안전합니다.

1. 앱 소개
============================================================
Ultra Random Prompt v8.0.0은 여러 ComfyUI 이미지 모델 등에서 사용할 수 있는 영어 프롬프트 문구를 버튼 선택으로 조합하는 단일 HTML 앱입니다.

이 앱의 주 기능은 이미지 생성 자체가 아니라 프롬프트 문구 작성·정리·복사입니다. 단, 선택적인 「AI 이미지 보기」 기능은 외부 OpenAI/Gemini API로 한 장짜리 이미지를 미리 생성할 수 있습니다. 이미지 분석은 반대로 참고 이미지를 영어 프롬프트로 설명합니다.

조합할 수 있는 요소:
- 피사체의 성별, 성인 연령, 인원, 외형과 세부 그룹 설정
- 표정, 시선, 포즈, 헤어·피부·메이크업, 의상·액세서리
- 배경, 시간대, 계절, 날씨, 조명, 분위기와 색감
- 사진, 애니·일러스트, 회화, 3D 등 스타일과 구도·렌즈
- 성인 NSFW의 별도 착의·노출·포즈·배경·조명·프리셋
- 사용자 커스텀 문구 및 아티스트 스타일 참고

이 버전에서도 Z-Image/Qwen/Flux/Anima/SD/SDXL/Pony/ILXL 등 특정 모델을 고르는 버튼은 없습니다. 프롬프트의 내용과 스타일을 직접 선택하고, 범용 자연어형 또는 태그형으로 출력합니다.

핵심 사용 원칙:
1. 중요 요소는 직접 고정하고 그 외 후보만 멀티·POOL로 랜덤화합니다.
2. 「자동·중립」은 특정 모델의 실사·애니 스타일을 임의 강제하지 않습니다. 직접 선택한 스타일이 우선입니다.
3. 「실사 / 일러스트·애니」는 기본 방향 보조이며, 사용자가 명확히 선택한 스타일을 덮어쓰지 않습니다.
4. NSFW는 성인용 프롬프트 문구 조합 기능입니다. 성인·연령 정확성은 지키되, 성인 콘텐츠의 표현 범위를 임의로 축소하지 않았습니다.

2. 가장 먼저 알아야 할 핵심 개념
============================================================

이 앱을 쓰기 전에 다음 네 가지 개념만 이해하면 됩니다.

첫째, 선택하지 않은 항목은 대부분 결과에 들어가지 않습니다.
예를 들어 신발을 고르지 않으면 결과 프롬프트에 신발 설명이 들어가지 않을 수 있습니다.

둘째, 일반 클릭은 “이 항목을 쓰겠다”는 뜻입니다.
예를 들어 배경에서 “비 오는 밤 네온 골목”을 클릭하면, 그 배경이 프롬프트에 들어갑니다.

셋째, Ctrl/⌘ 클릭은 “여러 후보 중 랜덤”입니다.
예를 들어 표정에서 미소, 무표정, 도도한 표정을 Ctrl로 여러 개 고르면, 생성할 때 그중 하나가 랜덤으로 들어갑니다.

넷째, 미선택 랜덤과 전체 랜덤은 다릅니다.
- 미선택 랜덤: 이미 선택한 항목은 유지하고, 비어 있는 곳만 자동으로 채웁니다.
- 전체 랜덤: 선택 여부와 상관없이 더 넓게 다시 랜덤 지정합니다.

처음에는 일반 클릭만 써도 됩니다. 익숙해지면 Ctrl/⌘ 클릭과 Shift 클릭을 사용하세요.

3. 화면 구성 전체 이해
============================================================
왼쪽은 프롬프트 재료와 프리셋을 선택하는 곳, 오른쪽은 출력 설정·미리보기·결과를 관리하는 곳입니다.

왼쪽 탭은 「인물 / 외모 / 장면 / 스타일 / NSFW」입니다. 탭별 슬롯에서 직접 선택, Ctrl/⌘ 후보 선택, Shift 하위 카테고리 지정 등을 사용할 수 있습니다.

오른쪽 상단:
- 출력 형식: 「자연어형 / 태그형」
- 기본 방향: 「자동·중립 / 실사 / 일러스트·애니」
- 자연어 길이: 「간결 / 표준 / 상세」(태그형에서는 적용하지 않음)
- 생성 개수: 1~100개
- 설정 저장 / 설정 갱신 / 설정 초기화

오른쪽 본문:
- 미리보기 샘플 1개, 복사·번역·AI 이미지 보기·수동 수정/적용/취소
- 현재 선택 요약 카드, 생성 결과 목록, 각 결과의 복사·번역·이미지 보기

주요 버튼:
- 「생성하기」: 현재 선택과 랜덤 후보를 바탕으로 결과를 만듭니다.
- 「미선택 랜덤」: 선택하지 않은 곳만 자동으로 채웁니다.
- 「전체 랜덤」: 기존 직접 선택과 멀티선택을 풀고 새로 랜덤화합니다.
- 「초기화」: 저장된 설정이 있으면 그 상태로 복귀하고, 없으면 기본 상태로 복귀합니다.

좁은 화면에서는 좌측 선택 패널을 상단 모바일 메뉴 버튼으로 열 수 있습니다. 패널 바깥을 누르거나 메뉴 버튼을 눌러 닫을 수 있습니다.

4. 처음 사용하는 사람을 위한 5분 사용법
============================================================
1. 왼쪽 「인물」에서 생성 대상과 성인 연령대, 성별, 인원수를 고릅니다. 풍경만 만들려면 「배경만 생성」을 선택합니다.
2. 「외모」에서 표정, 헤어, 의상 등을 필요할 만큼 선택합니다.
3. 「장면」에서 배경과 시간대·날씨·조명을 고릅니다.
4. 「스타일」에서 사진·애니·회화·3D 중 실제 원하는 스타일과 구도를 선택합니다.
5. 우측에서 「자연어형」을 선택하고 기본 방향은 우선 「자동·중립」으로 둡니다.
6. 내용이 없는 기본 인물에서 명확한 실사 또는 애니 방향을 원할 때만 「실사 / 일러스트·애니」를 사용합니다.
7. 자연어 길이는 「표준」으로 시작합니다. 간결은 일부 반복 수식어를 줄이고 상세는 이미 선택된 배경·조명·재질·카메라의 실제 시각적 관찰을 보강합니다.
8. 생성 개수를 5개 또는 10개로 정하고 「생성하기」를 누릅니다.
9. 결과를 복사해 사용하거나, 우측 미리보기에서 「수정」으로 문장을 직접 다듬습니다.
10. 원한다면 「AI 이미지 보기」로 한 장짜리 API 프리뷰를 생성하거나, 왼쪽 「이미지 분석」에서 참고 이미지의 영어 프롬프트를 추출합니다.

선택이 너무 많아 서로 충돌한다면 먼저 연령·인원·의상·배경·구도만 고정하고 나머지를 랜덤화해 보세요.

5. 왼쪽 선택 패널 사용법
============================================================

왼쪽 선택 패널은 프롬프트의 재료를 고르는 곳입니다.

버튼은 대부분 다음 방식으로 표시됩니다.

- 일반 상태: 아직 선택되지 않음
- 파란색 계열: 직접 선택됨
- 초록 점선 계열: 풀 지정 또는 후보 지정
- 노란 체크 표시: 멀티선택된 항목
- 회색/비활성: 현재 조건에서는 선택할 수 없음

선택 패널은 사용자가 원하는 것만 고르도록 설계되어 있습니다.
모든 슬롯을 채울 필요는 없습니다.

예를 들어 인물 이미지를 만들 때 반드시 신발을 고를 필요는 없습니다.
상반신 포트레이트라면 신발은 보이지 않기 때문에 신발 설명이 없어도 됩니다.

반대로 전신샷이나 패션 이미지에서는 신발, 하체 의상, 액세서리까지 고르면 더 좋습니다.

6. 생성 대상: 배경만 생성, 이미지 분석, 툴팁
============================================================

왼쪽 상단 생성 대상 영역에는 중요한 버튼들이 있습니다.

------------------------------------------------------------
6-1. 배경만 생성
------------------------------------------------------------

배경만 생성은 인물 없이 장면이나 배경을 만들 때 사용합니다.

예:
- 비 오는 밤의 네온 골목
- 안개 낀 숲
- 고급 호텔 로비
- 미래 도시
- 폐허가 된 거리
- 판타지 성 내부

배경만 생성을 켜면 인물, 외형, 의상, 포즈 같은 항목은 결과에서 제외되거나 약화됩니다.
현재 버전에서는 배경만 모드에서 인물 중심 이벤트가 다시 끼어들지 않도록 보정되어 있습니다.
예를 들어 데이트, 쇼핑, 공연 대기, 스튜디오 촬영 같은 인물 중심 이벤트는 배경만 모드에서 자동으로 재삽입되지 않도록 정리되어 있습니다.

배경만 생성에서는 다음 항목을 고르는 것이 좋습니다.

- 배경
- 시간대
- 계절
- 날씨
- 조명
- 분위기
- 색감
- 스타일
- 구도
- 렌즈

------------------------------------------------------------
6-2. 이미지 분석
------------------------------------------------------------

이미지 분석은 메인 POOL 선택과 섞이지 않는 독립 기능입니다.
버튼을 누르면 별도 레이어 창이 열립니다.
그 창 안에서 이미지를 업로드하고, GPT, Gemini, Ollama Vision 중 하나로 이미지를 분석해 영어 프롬프트 1개를 만듭니다.

이미지 분석은 다음 상황에 좋습니다.

- 참고 이미지와 비슷한 프롬프트를 만들고 싶을 때
- 사진, 애니, 일러스트, 수채화, 3D 등 스타일을 추적하고 싶을 때
- 조명, 배경, 구도, 색감, 분위기를 텍스트로 뽑고 싶을 때
- Civitai나 다른 이미지의 느낌을 프롬프트로 재구성하고 싶을 때

중요:
- 이미지 분석은 이미지 생성 기능이 아닙니다.
- 이미지 분석 결과는 메인 POOL 선택값과 자동으로 합쳐지지 않습니다.
- 분석 결과는 이미지 분석창 안에서 확인, 복사, 번역합니다.
- 이미지 분석창을 닫아도 진행 중인 요청은 페이지가 열려 있는 동안 계속 처리되며, 다시 열어 결과·오류를 확인할 수 있습니다. 초기화는 업로드 이미지와 분석 결과를 삭제합니다.

지원 방식:
- GPT 이미지 분석: OpenAI API 키 필요
- Gemini 이미지 분석: Gemini API 키 필요
- Ollama Vision 이미지 분석: API 키 불필요, 로컬 Ollama 실행 필요

Ollama 주의:
Ollama는 로컬 Vision 모델로 이미지를 분석하는 보조 기능입니다.
일반 텍스트 모델은 이미지를 볼 수 없으므로 정상 분석이 불가능합니다.
Ollama 결과는 GPT/Gemini보다 간단하거나 품질 편차가 있을 수 있습니다.

------------------------------------------------------------
6-3. 툴팁
------------------------------------------------------------

툴팁은 POOL 항목의 설명을 보여주는 기능입니다.
PC에서 마우스를 올리면 설명 카드가 나타납니다.

툴팁 ON:
- 항목의 의미를 쉽게 확인할 수 있습니다.

툴팁 OFF:
- 화면을 더 깔끔하게 쓸 수 있습니다.
- 항목을 빠르게 선택할 때 방해가 줄어듭니다.

7. 일반 클릭, Ctrl/⌘ 클릭, Shift 클릭
============================================================

이 앱의 선택 방식은 세 가지입니다.

------------------------------------------------------------
7-1. 일반 클릭
------------------------------------------------------------

일반 클릭은 한 슬롯에서 하나를 고정 선택하는 방식입니다.

예:
표정에서 “미소”를 클릭하면 미소가 선택됩니다.
그 뒤 “무표정”을 클릭하면 미소는 해제되고 무표정이 선택됩니다.

즉 일반 클릭은 “이 슬롯은 이 항목 하나로 고정하겠다”는 의미입니다.

------------------------------------------------------------
7-2. Ctrl/⌘ 클릭
------------------------------------------------------------

Windows는 Ctrl, Mac은 ⌘ 키를 사용합니다.

Ctrl/⌘ 클릭은 여러 항목을 후보로 선택하는 방식입니다.

예:
표정에서 다음을 Ctrl로 클릭합니다.
- 미소
- 차분한 표정
- 도도한 표정

그러면 생성할 때 이 세 표정 중 하나가 랜덤으로 선택됩니다.

이 방식은 “원하는 범위 안에서만 랜덤”을 만들 때 좋습니다.

------------------------------------------------------------
7-3. Shift 클릭
------------------------------------------------------------

Shift 클릭은 현재 누른 하위 카테고리 내부 항목만 전체 선택하거나 해제합니다.

예:
의상 압축 보기에서 캐주얼 하위 카테고리 안의 항목을 Shift 클릭하면, 캐주얼 하위 카테고리 내부 항목만 후보가 됩니다.
포멀, 유니폼, 판타지 같은 다른 하위 카테고리는 함께 건드리지 않습니다.

다시 같은 하위 카테고리에서 Shift 클릭하면 그 하위 카테고리 내부 후보가 해제됩니다.

이 기능은 데이터가 많은 압축 보기에서 원하는 범위만 빠르게 후보화할 때 특히 유용합니다.
대표/전체 버튼은 보기 전환용이며, Shift 일괄 선택의 기준은 실제 항목이 속한 하위 카테고리입니다.

============================================================
8. 직접 선택, 멀티선택, 풀 지정의 차이
============================================================

------------------------------------------------------------
8-1. 직접 선택
------------------------------------------------------------

직접 선택은 반드시 결과에 들어가야 하는 항목입니다.

예:
- 한국인 여성
- 비 오는 밤 네온 골목
- 쓰리쿼터샷
- 시네마틱 조명

중요한 컨셉은 직접 선택하는 것이 좋습니다.

------------------------------------------------------------
8-2. 멀티선택
------------------------------------------------------------

멀티선택은 사용자가 고른 후보 중 하나가 랜덤으로 들어가는 방식입니다.

예:
의상 후보:
- 검은 원피스
- 흰 셔츠
- 데님 재킷

생성할 때마다 이 중 하나가 들어갑니다.

중요:
직접 멀티선택한 후보들은 item 단위 균등 확률입니다.
예를 들어 서로 다른 세부 pool에서 총 5개 후보를 직접 선택했다면, 5개 모두 각각 20% 확률입니다.
이때 ITEM_BIAS나 GROUP_BIAS는 적용되지 않습니다.

------------------------------------------------------------
8-3. 풀 지정
------------------------------------------------------------

풀 지정은 해당 슬롯의 전체 pool에서 랜덤으로 뽑는 방식입니다.

예:
날씨를 풀 지정하면 맑음, 비, 눈, 안개 등 전체 날씨 pool에서 하나가 랜덤으로 나올 수 있습니다.

풀 지정은 결과 다양성을 크게 늘립니다.

중요:
초록 점선 풀 랜덤은 직접 멀티선택과 다릅니다.
풀 랜덤은 앱에 설정된 GROUP_BIAS와 ITEM_BIAS 가중치를 사용합니다.
따라서 자주 쓰기 좋은 기본 항목은 더 자주 나오고, 특수한 항목은 상대적으로 덜 나올 수 있습니다.

============================================================
9. 압축 보기와 하위 카테고리 사용법
============================================================

이 앱은 항목 수가 많아서 모든 데이터를 한 화면에 그대로 보여주면 너무 길어집니다.
그래서 일부 슬롯은 압축 보기 구조를 사용합니다.

압축 보기에는 보통 다음 버튼이 있습니다.

- 대표
- 전체
- 하위 카테고리

대표는 자주 쓰는 항목만 보여줍니다.
전체는 모든 항목을 보여줍니다.
하위 카테고리는 특정 종류만 보여줍니다.

예를 들어 의상 슬롯이라면:
- 캐주얼
- 포멀
- 유니폼
- 판타지
- 계절/외투

같은 식으로 나뉠 수 있습니다.

압축 보기에서도 선택 방식은 같습니다.

- 일반 클릭: 하나 고정
- Ctrl/⌘ 클릭: 후보 추가/해제
- Shift 클릭: 클릭한 항목이 속한 하위 카테고리 내부 전체 선택/해제(접혀서 보이지 않는 항목 포함)

하위 카테고리 버튼에 숫자가 표시될 수 있습니다.
그 숫자는 그 카테고리 안에서 선택된 항목 수입니다.

============================================================
10. 오른쪽 출력 패널 사용법
============================================================
오른쪽 출력 패널의 설정:
1. 출력 형식: 자연어형 또는 태그형
2. 기본 방향: 자동·중립 / 실사 / 일러스트·애니
3. 자연어 길이: 간결 / 표준 / 상세
4. 생성 개수: 최대 100개
5. 설정 저장·갱신·초기화
6. 현재 선택 요약, 미리보기, 결과 리스트

특정 생성 모델을 고르는 버튼은 없습니다. 출력 형식을 바꿔도 피사체·의상·배경 등 선택 내용 자체가 새 모델에 맞게 임의로 바뀌도록 의도한 기능은 아닙니다.

기본 방향은 사용자가 스타일을 직접 고르지 않은 상황의 기본 시각적 성향을 보조합니다. 개별 스타일 선택이 있으면 그것이 우선합니다.

자연어 길이 옵션은 태그형에 적용되지 않습니다. 「간결」은 내용을 빼는 강제 축약이 아니라 일부 반복 수식어를 줄이는 조정이며, 「상세」는 현재 선택된 시각적 요소에 근거해 배경 깊이·조명·재질·카메라 묘사를 보강합니다.

미리보기는 현재 선택 상태의 샘플 1개이고, 결과 리스트는 생성 후 여러 후보를 보여줍니다. 다중 후보가 있으면 미리보기와 결과의 구체적 선택은 달라질 수 있습니다.

============================================================
11. 자연어형과 태그형 차이
============================================================
11-1. 자연어형
- 피사체·행동·장면·조명·구도를 연결된 영어 문장으로 설명합니다.
- 특정 생성 모델명이 아니라 실제 장면과 시각적 특징에 초점을 맞춥니다.
- 길이 옵션 「간결/표준/상세」를 사용할 수 있습니다.

예시(설명용):
An adult East Asian woman standing in a rainy neon alley, wearing a black jacket, framed in a cinematic three-quarter shot with wet pavement reflections and soft blue-magenta lighting.

11-2. 태그형
- 쉼표로 구분된 단어·짧은 구문을 출력합니다.
- 예전 태그 중심 워크플로우 또는 사용자의 TAG 커스텀 값을 위해 보존된 범용 출력입니다.
- SD/Pony/ILXL 등 모델 선택 버튼이나 score 전용 프로필은 없습니다.
- 자연어 길이 옵션은 적용하지 않습니다.

예시(설명용):
1woman, adult, East Asian, rainy neon alley, black jacket, three-quarter shot, cinematic lighting, wet pavement, blue magenta palette

태그형을 유지했다고 해서 단부루 태그나 특정 점수 접두어가 모든 모델에 적합하다는 뜻은 아닙니다. 대부분의 현대 이미지 모델에서는 자연어형부터 시도하는 편이 무난합니다.

============================================================
12. 자연어형/태그형 전환과 자동 재생성
============================================================
출력 형식, 기본 방향, 자연어 길이를 변경하면 생성 결과가 현재 설정에 맞게 다시 표시됩니다.

예시:
1. 자연어형·자동·중립·표준으로 10개 생성
2. 「태그형」으로 바꾸면 기존에 뽑힌 내용 조합을 태그 형태로 다시 조립
3. 「자연어형」으로 돌아오면 자연어 형태로 다시 조립
4. 기본 방향을 「실사」로 바꾸면 현재 선택을 기준으로 실사 성향 보조를 적용
5. 자연어 길이를 「상세」로 바꾸면 선택한 배경·빛·재질·구도에 근거한 시각 묘사를 확장

주의:
- Z-Image/Qwen/FLUX/Anima/SDXL/Pony 등 개별 이미지 모델을 선택하는 버튼은 없습니다. 프롬프트의 출력 방식과 시각 방향을 선택합니다.
- 자동 결과 조립과 미리보기 내부에는 랜덤 후보가 존재하므로 새로 생성했을 때 문장이 달라질 수 있습니다.
- 결과를 완전히 직접 수정하고 싶다면 「미리보기 → 수정 → 적용」을 이용하세요. 출력 설정이나 원본 선택을 바꾸면 수동 수정 상태가 영향을 받을 수 있으므로 별도로 복사해 두는 것이 안전합니다.

============================================================
13. 범용 출력: 기본 방향과 자연어 길이
============================================================
13-1. 기본 방향
- 「자동·중립」: 특정 모델 이름이나 기본 실사/애니 스타일을 강제하지 않는 기본값입니다.
- 「실사」: 별도 스타일을 고르지 않은 경우 사진·실사 성향을 보조합니다.
- 「일러스트·애니」: 별도 스타일을 고르지 않은 경우 일러스트·애니 성향을 보조합니다.
- 어느 방향이든 사용자가 POOL 또는 커스텀으로 명확히 선택한 스타일은 우선 반영합니다.

13-2. 자연어 길이
- 「간결」: 사용자가 선택한 요소는 유지하고, 자동으로 붙는 상투 연결·중복 장식 묘사를 축약합니다.
- 「표준」: 기존 풍부한 장면 묘사를 최대한 유지하는 기본값입니다.
- 「상세」: 실제 선택된 배경 깊이·빛과 그림자·의상 재질·피부 음영·촬영 특성을 근거로 시각적 관찰 문장을 보강합니다. 새 인물·행위·장소를 임의로 요구하지 않습니다.
- 세 옵션 모두 사용자가 선택한 인물·의상·포즈·성인 NSFW 세부 표현을 임의 삭제하는 목적이 아닙니다.
- 자연어 길이 설정은 「태그형」 결과에는 적용되지 않습니다.

13-3. 저장 설정과 기기 환경
- 저장 설정은 브라우저의 저장 영역에 보관됩니다. 같은 브라우저·같은 저장 출처에서는 다시 열 때 복원될 수 있습니다.
- 파일 위치·브라우저·개인정보 보호 설정이 바뀌면 저장 영역이 달라져 복원이 보이지 않을 수 있습니다.
- 저장된 직접 선택과 Ctrl/⌘ 후보, 랜덤 POOL 상태가 함께 복원됩니다.
- KO/EN 화면 표시 언어는 선택값과 별도로 보관되며 생성되는 영어 문장을 바꾸지 않습니다.

13-4. 한·영 UI 관련 안내
- 상단 KO/EN 스위치로 화면 언어를 바꿀 수 있습니다. 프롬프트 원문과 선택 상태는 유지됩니다.
- 이미지 분석의 한국어 지시어 입력과 영어 프롬프트 출력은 UI 표시 언어와 별개입니다. KO/EN 화면 전환은 분석 결과의 내용이나 언어 지시를 바꾸지 않습니다.

============================================================
13-A. 아티스트 입력 기능
============================================================
아티스트 입력은 인물 탭의 별도 「아티스트 입력/수정」 버튼에서 여는 스타일 참고 기능입니다. 일반 POOL의 랜덤 후보에 섞지 않고 최종 프롬프트 출력에 반영합니다.

기본 조작:
- 버튼을 눌러 아티스트 입력창 열기
- 이름 또는 여러 이름 입력: 쉼표, 줄바꿈, 세미콜론 구분 가능
- 「+ 아티스트 추가」로 새로운 빈 행 만들기
- 「적용」: 현재 입력값을 반영하되 창은 유지
- 「모두 삭제」: 아티스트 목록만 비우며 창은 유지
- 「닫기/X」: 창만 닫기

입력 예: Syd Mead, Moebius, Yoshitaka Amano
- `@Syd Mead`, `by Moebius` 등 불필요한 접두어는 가능한 범위에서 정리됩니다.
- 가중치는 선택 사항이며 1.2, 2.7, 5 같은 값을 넣을 수 있습니다. 현재 입력은 부호를 제거한 절댓값으로 정규화하므로 -1은 1, -0.5는 0.5로 해석됩니다. 음수로 약화하는 기능은 지원하지 않으며 지나치게 큰 가중치는 피하는 것이 좋습니다.

이 앱의 출력 방식:
- 자연어형: `In the style of Syd Mead, using the artist's overall visual image style as a visual reference ...` 등 문장형 참고로 반영됩니다.
- 자연어형: 숫자 가중치를 프롬프트에 직접 넣지 않고 `light / strong / dominant visual reference` 등 표현 강도로 바꿉니다.
- 태그형: `Syd Mead` 또는 `(Syd Mead:1.2)`처럼 일반 태그와 선택적 가중치로 넣습니다.
- 과거 Anima 전용 `@artist` 형식과 Z/Qwen/Flux별 서로 다른 아티스트 문법은 **현재 출력 기능이 아닙니다**.

아티스트만 입력하고 다른 프롬프트 슬롯을 고르지 않으면 내용 선택이 없는 것으로 처리될 수 있습니다. 먼저 일반 선택 또는 미선택/전체 랜덤으로 피사체·장면을 구성하세요.

아티스트는 일반·성인 NSFW·배경만 생성에 공통 적용되며, 저장 설정에 포함됩니다. 좌하단 초기화는 현재 아티스트 입력을 유지하고, 우상단 설정 초기화는 저장된 아티스트 선택 설정도 삭제합니다.

아티스트 입력에는 임의 HTML·스크립트 조각 등을 사용하지 마세요. 실제 생성 모델이 작가 이름을 이해하는지는 해당 모델의 학습 특성에 따라 다릅니다.

============================================================
14. 생성 개수와 결과 리스트
============================================================

생성 개수는 한 번에 만들 프롬프트 수입니다.

1개:
- 하나만 빠르게 확인할 때

5개:
- 여러 후보를 비교할 때

10개:
- 일반적인 추천값

20개 이상:
- 많은 랜덤 조합을 보고 싶을 때

생성 개수가 많을수록 다양한 결과를 볼 수 있지만, 결과를 고르는 데 시간이 더 걸립니다.

멀티선택이나 풀 지정이 많을수록 여러 개 생성했을 때 차이가 더 크게 나타납니다.

============================================================
15. 미리보기와 결과 리스트의 차이
============================================================

미리보기는 현재 선택 상태의 샘플 1개입니다.
결과 리스트는 생성 버튼을 눌렀을 때 만들어지는 실제 여러 개의 결과입니다.

미리보기는 선택을 바꾸면 즉시 바뀔 수 있습니다.
결과 리스트는 생성 버튼을 눌러 새 조합을 만들며, 출력 형식·방향·길이 전환 시에는 가능한 범위에서 기존 조합을 재표현합니다. 방향 전환이 자동 스타일을 다시 선택하는 경우 해당 스타일 표현은 갱신될 수 있습니다.

즉 미리보기와 결과 리스트가 항상 같은 것은 아닙니다.
랜덤 후보가 있으면 미리보기와 결과 리스트의 항목이 달라질 수 있습니다.

============================================================
16. 복사, 번역, 이미지 버튼 사용법
============================================================

결과 리스트의 각 프롬프트에는 버튼이 표시됩니다.

복사:
- 해당 프롬프트를 클립보드에 복사합니다.

번역:
- 자연어형 결과에서 한국어 번역 레이어를 띄웁니다.
- 태그형에서는 보통 번역 버튼이 표시되지 않습니다.

이미지:
- 해당 프롬프트를 AI 이미지 미리보기 레이어로 보냅니다.
- 기본 프리뷰는 GPT Image 2입니다. 실제 비용은 현재 API 요금표를 확인하세요.
- 레이어 안에서 Gemini 3.1 Flash Lite Image로 변경할 수 있습니다.

============================================================
17. AI 이미지 미리보기 기능
============================================================
AI 이미지 미리보기는 프롬프트 문구를 평가하기 위한 **선택 기능**입니다. 앱의 기본 사용에는 필요하지 않습니다. 결과의 「이미지」 또는 미리보기의 「AI 이미지 보기」를 눌렀을 때만 외부 API로 이미지 1장을 생성합니다.

지원 공급자와 모델:
- OpenAI: `gpt-image-2` (화면명 GPT Image 2), `https://api.openai.com/v1/images/generations`
  · 요청 크기 1024×1024, quality low, 1장
- Gemini: `gemini-3.1-flash-lite-image` (화면명 Gemini 3.1 Flash Lite Image)
  · `generateContent`, 응답 IMAGE, 정사각형 1K, 1장

사용 순서:
1. 텍스트 프롬프트를 생성하거나 미리보기에서 수정합니다.
2. 「이미지」 또는 「AI 이미지 보기」를 눌러 이미지 미리보기 창을 엽니다.
3. OpenAI 또는 Gemini 중 하나를 선택합니다.
4. 필요한 경우 API 키를 입력합니다.
5. 생성 버튼을 누르고 결과를 확인합니다. 재생성 때마다 사용량이 추가될 수 있습니다.

주의:
- GPT와 Gemini의 분석 모델은 이 이미지 생성 모델과 별개입니다.
- GPT Image 2와 Gemini 3.1 Flash Lite Image 모두 무료 API 티어가 없습니다. 각 제공사의 유료 API 결제 설정과 잔여 한도를 확인하세요. ChatGPT 구독과 OpenAI API 결제는 별개입니다.
- Gemini 원본 오류에 `generate_content_free_tier_requests` 및 `limit: 0`이 나타나면 이 모델의 무료 사용 한도가 0이라는 뜻입니다. 무료 티어에서 재시도나 프롬프트 변경으로 해결되지 않습니다.
- API 오류가 발생하면 「원본 오류 보기」를 펼쳐 실제 제공사의 응답을 확인하세요. 한글·영문 화면 모두 동일한 원본 응답을 보존합니다.
- 저장할 때 생성된 이미지의 실제 형식(PNG/JPEG/WebP)에 맞게 확장자를 사용합니다. 히스토리에서 이전 이미지를 저장하면 해당 이미지를 만든 공급자 이름을 파일명에 사용합니다.
- Ollama는 현재 앱에서 이미지 **분석 전용**이며, 이미지 생성 공급자로는 표시되지 않습니다.
- 외부 API의 안전 정책에 따라 앱에서 만든 성인 NSFW 프롬프트라도 이미지 미리보기 요청이 거부될 수 있습니다. 앱 내부의 문구 작성·선택 자유도와 별개인 사항입니다.
- 이 앱은 이미지 모델별 요청 형식을 구현했지만, 제공사에서 지원 조건이나 모델 ID를 바꾸면 코드도 업데이트해야 할 수 있습니다.

============================================================
18. 이미지 분석 기능
============================================================
이미지 분석은 업로드한 이미지를 읽고, 그 시각적 내용을 **영어 이미지 생성 프롬프트 1개**로 작성하는 독립 도구입니다. 메인 POOL·랜덤 선택·생성 결과와 자동 결합하지 않습니다.

현재 분석 공급자:
- OpenAI: GPT-5.4 mini (`gpt-5.4-mini`) — OpenAI API 키 필요
- Gemini: Gemini 3.1 Flash-Lite (`gemini-3.1-flash-lite`) — Gemini API 키 필요
- Ollama: 사용자가 설치한 Vision 지원 모델 — 로컬 API 키 불필요

기본 사용법:
1. 「인물」 탭 근처의 「이미지 분석」 버튼을 누릅니다.
2. OpenAI, Gemini, Ollama Vision 중 하나를 선택합니다.
3. OpenAI/Gemini는 API 키를 등록하거나 임시 키를 입력합니다.
4. Ollama는 모델 목록을 불러와 Vision 지원 상태를 확인한 뒤 모델을 선택합니다.
5. PNG/JPEG/WEBP 등 지원 이미지를 업로드합니다.
6. 필요하면 한국어 커스텀 지시어를 입력합니다.
7. 분석 실행 후 영어 결과를 확인하고 복사하거나 번역합니다.

요청 처리:
- OpenAI는 Chat Completions에 이미지 입력과 `max_completion_tokens`를 사용합니다.
- Gemini는 `generateContent`에서 `x-goog-api-key` 헤더와 이미지 입력을 사용합니다.
- Ollama는 `/api/chat`에 이미지와 `think: false`를 포함해 요청합니다.
- Ollama가 `thinking`만 반환하고 본문이 비어 있으면 추론 내용을 프롬프트로 대체하지 않습니다.
- 외부 OpenAI/Gemini 분석용 이미지 최대 변은 기본적으로 1536px, Ollama 분석용은 768px로 조절할 수 있습니다.

이미지 분석창 「닫기」는 현재 페이지에서 진행 중인 요청을 중단하지 않습니다. 분석 완료 후 다시 열어 결과 또는 오류를 확인할 수 있습니다. 「초기화」는 업로드 이미지·분석 결과·임시 키·임시 지시어를 정리하며, 분석 중에는 초기화할 수 없습니다. 페이지 새로고침·종료는 진행 중 요청을 중단할 수 있습니다. 저장된 API 키는 별도 관리 대상으로 유지됩니다.

오류 유형:
- API 키 없음, 계정·모델 권한 문제, 429/할당량, 네트워크·브라우저 정책 문제
- Ollama 로컬 서버 연결 불가와 모델 Vision 미지원은 별개의 상태입니다.
- 실제 분석 품질과 한국어 지시 이해도는 모델에 따라 다릅니다.

============================================================
19. 이미지 분석 커스텀 지시어 사용법
============================================================

커스텀 지시어는 이미지 분석 방향을 조절하는 입력칸입니다.
한국어로 입력해도 됩니다.
최종 결과 프롬프트는 영어로 출력됩니다.

예:

조명과 배경을 더 강조하고 인물 묘사는 간결히 해줘.

결과:
- 조명, 배경, 분위기가 더 강하게 반영된 영어 프롬프트가 생성됩니다.

예:

의상과 소재감을 자세히 분석해줘.

결과:
- 옷의 색, 재질, 실루엣, 질감이 더 자세히 들어갈 수 있습니다.

Ollama에서의 주의:
- 한국어 지시어 입력은 가능합니다.
- 다만 로컬 Vision 모델마다 한국어 이해력과 프롬프트 작성 품질이 다릅니다.
- 앱은 최종 결과를 영어 이미지 생성 프롬프트로 정리하도록 지시합니다.
- Ollama가 한국어 중심 응답을 반환하거나 이미지를 보지 못했다는 응답을 하면 실패로 처리될 수 있습니다.

좋은 커스텀 지시어:
- 조명과 배경을 더 강조해줘.
- 의상과 소재감을 자세히 분석해줘.
- 구도와 카메라 거리감을 중심으로 정리해줘.
- 원본 스타일을 유지하되 영어 이미지 생성 프롬프트로 압축해줘.

주의:
커스텀 지시어는 이미지를 변형하는 기능이 아닙니다.
예를 들어 원본이 사진인데 “수채화로 바꿔줘”라고 쓰면 분석 기능의 본래 목적과 충돌할 수 있습니다.
이미지 분석은 원본 이미지의 모습, 스타일, 조명, 구도를 최대한 충실하게 프롬프트로 옮기는 기능입니다.

20. API 키 입력, 저장, 삭제
============================================================

API 기능을 사용할 때는 기능별로 필요한 조건이 다릅니다.

API 키가 필요한 기능:
- AI 이미지 미리보기 OpenAI
- AI 이미지 미리보기 Gemini
- 이미지 분석 OpenAI
- 이미지 분석 Gemini

API 키가 필요 없는 기능:
- Ollama Vision 이미지 분석

단, Ollama는 API 키가 필요 없을 뿐이며, 로컬 Ollama가 실행 중이어야 합니다.
또한 이미지 분석에는 Vision 지원 모델이 필요합니다.

API 키는 레이어 안에서 입력할 수 있습니다.
브라우저에 저장하도록 체크하면 localStorage에 저장됩니다.
저장하지 않으면 현재 창에서만 임시로 사용합니다.

키가 없을 때도 이미지 분석 버튼이나 이미지 미리보기 버튼은 열립니다.
다만 GPT/Gemini 실행에는 레이어 안에서 키를 입력해야 합니다.
Ollama는 키 입력창 대신 모델 목록과 Vision 안내가 표시됩니다.

저장된 API 키 삭제는 각 레이어의 키 관리 버튼에서 할 수 있습니다.
Ollama는 저장 API 키가 없으므로 삭제할 키가 없습니다.

주의:
localStorage에 저장된 키는 해당 브라우저/파일 환경에 저장됩니다.
공용 PC에서는 저장하지 않는 것이 좋습니다.

21. API 키 하드코딩 방법
============================================================

하드코딩은 HTML 소스 안에 API 키를 직접 넣는 방식입니다.
개인용으로만 사용하세요.
API 키가 들어간 HTML 파일은 절대로 공유하지 마세요.

하드코딩 대상:
- OpenAI API 키
- Gemini API 키

하드코딩 대상이 아닌 것:
- Ollama

Ollama는 로컬 서버와 설치된 모델을 사용하므로 API 키를 HTML에 넣지 않습니다.
Ollama가 필요하면 Ollama 앱을 실행하거나 터미널에서 ollama serve를 실행하고, Vision 모델을 설치해야 합니다.

OpenAI 키 넣기:

1. HTML 파일을 텍스트 편집기로 엽니다.
2. 다음 문구를 검색합니다.

keyLabel: 'OpenAI API 키'

3. 근처의 아래 줄을 찾습니다.

hardcodedApiKey: '',

4. 따옴표 안에 키를 넣습니다.

예:

hardcodedApiKey: 'sk-xxxxxxxxxxxxxxxx',

Gemini 키 넣기:

1. 다음 문구를 검색합니다.

keyLabel: 'Gemini API 키'

2. 근처의 아래 줄을 찾습니다.

hardcodedApiKey: '',

3. 따옴표 안에 Gemini 키를 넣습니다.

예:

hardcodedApiKey: 'AIzaSyxxxxxxxxxxxxxxxx',

중요:
줄 번호는 참고용입니다.
소스가 조금만 바뀌어도 줄 번호는 달라집니다.
항상 keyLabel 문구로 찾는 것이 안전합니다.

하드코딩 키를 제거하려면 다시 빈 값으로 바꾸면 됩니다.

hardcodedApiKey: '',

22. API 모델명·요청 형식 변경 시 주의
============================================================
앱의 HTML 소스에서 API 설정을 직접 변경하는 경우, 모델명만 바꿔서는 정상 동작을 보장할 수 없습니다. 반드시 제공사 문서와 요청/응답 계약을 함께 확인하세요.

현재 이 앱의 코드 검색 기준:
- 이미지 미리보기 OpenAI: `model: 'gpt-image-2'`
- 이미지 미리보기 Gemini: `gemini-3.1-flash-lite-image:generateContent`
- 이미지 분석 OpenAI: `model: 'gpt-5.4-mini'`
- 이미지 분석 Gemini: `model: 'gemini-3.1-flash-lite'`
- Ollama 분석: `ollamaBaseUrl: 'http://localhost:11434'` 및 `/api/tags`, `/api/show`, `/api/chat`

변경 시 확인 사항:
1. 모델 ID와 해당 계정의 접근 권한
2. API 엔드포인트, 인증 헤더, 이미지 입력 형식
3. 요청 옵션(예: `max_completion_tokens`, `reasoning_effort`, Gemini `thinkingLevel`)
4. 이미지 생성 결과의 base64 추출 키, MIME 유형, 크기·품질 옵션
5. 토큰·이미지 비용, 할당량, 지원 종료 일정
6. 오류 처리, 응답이 비었을 때의 안내, 브라우저 CORS 정책

특히 `gpt-image-2`와 `gpt-5.4-mini`는 다른 역할의 모델입니다. 분석 모델을 이미지 생성에 넣거나 반대로 사용하는 방식은 현재 코드와 맞지 않습니다.

Ollama 모델은 HTML에 한 모델명으로 고정되어 있지 않습니다. 실행 중인 서버의 모델 목록에서 선택합니다. `/api/show`가 반환하는 `capabilities`에 `vision`이 있는지를 확인하며, 확인 불가 모델은 경우에 따라 시도를 허용합니다.

23. 설정 저장 / 설정 초기화 / 좌하단 초기화
============================================================

앱에는 선택 설정 저장 기능이 있습니다. 이 기능은 현재 화면을 초기화하는 기능과 분리해서 이해하는 것이 좋습니다.

설정 저장:
- 현재 선택 상태를 브라우저 localStorage에 저장합니다.
- 아티스트 입력 상태도 설정 저장 대상입니다.
- 저장된 설정이 있으면 다음 실행 때 자동 복원됩니다.
- 이미 저장된 설정이 있으면 같은 버튼이 설정 갱신 역할을 합니다.

설정 초기화:
- 저장된 선택 설정 자체를 삭제하는 버튼입니다.
- 저장 설정에 포함된 아티스트 입력 상태도 함께 삭제됩니다.
- 저장 설정이 필요 없을 때만 사용합니다.
- 현재 화면도 공개본 기본값으로 정리됩니다.
- 이 버튼은 좌하단 초기화와 다릅니다.

좌하단 전체 초기화:
- 현재 화면과 선택 상태를 공개본 기본값 또는 저장 설정 상태로 되돌립니다.
- 아티스트 입력 상태는 좌하단 초기화로 삭제하지 않습니다.
- 저장된 선택 설정은 삭제하지 않습니다.
- 저장된 API 키도 삭제하지 않습니다.
- 저장된 설정이 남아 있으면 다음 실행 또는 새로고침 때 다시 자동 복원될 수 있습니다.

============================================================
24. 좌하단 초기화의 정확한 의미
============================================================

좌하단 초기화는 저장된 선택 설정이 있으면 그 저장 상태로 되돌리고, 저장된 선택 설정이 없을 때만 공개본 기본값으로 되돌립니다.

초기화되는 것:

- 직접 선택한 항목
- 멀티선택
- 풀 지정
- 커스텀 입력
- 프리셋 적용 상태
- 압축 보기 위치
- 자연어형/태그형 선택
- 기본 방향 및 자연어 길이 설정
- 생성 개수
- 결과 리스트
- 미리보기
- 이미지 분석 업로드 이미지
- 이미지 분석 결과 프롬프트
- 이미지 분석 임시 API 키
- 이미지 분석 커스텀 지시어

초기화되지 않는 것:

- 저장된 선택 설정
- 저장된 아티스트 입력 상태
- 저장된 OpenAI API 키
- 저장된 Gemini API 키

즉 “초기화”는 현재 화면을 정리하는 기능입니다.
저장된 설정을 삭제하는 기능이 아닙니다.
저장된 설정을 삭제하려면 우상단 설정 영역의 설정 초기화 버튼을 따로 사용합니다. 저장된 설정은 다음 실행 때 자동 복원되는 용도이며, 좌하단 초기화는 그 저장값을 삭제하지 않습니다.


------------------------------------------------------------
24-1. 좌하단 초기화와 우상단 설정 초기화의 차이
------------------------------------------------------------

이 두 버튼은 이름이 비슷하지만 역할이 다릅니다.

좌하단 초기화:
- 현재 작업 화면을 공개본 기본 상태 또는 저장 설정 상태로 되돌립니다.
- 선택 항목, 프리셋, 출력 형식, 기본 방향, 자연어 길이, 생성 개수, 결과 리스트, 이미지 분석 상태가 정리됩니다.
- 아티스트 입력 상태는 좌하단 초기화로 삭제하지 않습니다.
- 하지만 브라우저에 저장해 둔 선택 설정은 삭제하지 않습니다.
- 저장된 API 키도 삭제하지 않습니다.

우상단 설정 초기화:
- 저장된 선택 설정 자체를 삭제합니다.
- 저장 설정에 포함된 아티스트 입력 상태도 삭제합니다.
- 저장된 설정이 있는 상태에서 정말 공장 초기화에 가깝게 정리하고 싶을 때 사용합니다.
- 단, OpenAI/Gemini 저장 API 키는 별도 키 관리 대상이므로 이 버튼으로 삭제되지 않습니다.

실제 예시:
1. 자주 쓰는 기본 세팅을 만든다.
2. 우상단 설정 저장을 누른다.
3. 여러 항목을 바꾸며 실험한다.
4. 좌하단 초기화를 누른다. 저장된 세팅이 있으면 그 저장 상태로 돌아가고, 저장 세팅 자체는 남아 있다.
5. 저장 세팅 자체를 삭제하고 싶을 때만 우상단 설정 초기화를 누른다.
6. 저장 설정을 다시 자동 적용하고 싶다면 HTML을 다시 열거나 새로고침한다.

------------------------------------------------------------
33-1. NSFW 선택/탭 오픈 상태에서 일반 항목과 NSFW 항목의 관계
------------------------------------------------------------

NSFW 항목을 하나라도 선택했거나 NSFW 탭이 열린 상태에서 미선택 랜덤/전체 랜덤을 사용하면, 앱은 그 상태를 NSFW 생성 흐름으로 봅니다.

이때 모든 일반 항목이 사라지는 것은 아닙니다.
같은 성격으로 겹치는 항목은 NSFW 쪽이 우선하고, 겹치지 않는 항목은 일반 쪽을 계속 사용합니다.

NSFW 쪽이 우선하는 대표 항목:
- 일반 의상 ↔ NSFW 착의, 노출 단계, 누드 성격
- 일반 배경 ↔ NSFW 배경
- 일반 조명 ↔ NSFW 조명
- 일반 포즈/행동 일부 ↔ NSFW 포즈, 행위, 보조 강조 항목

계속 일반 쪽을 사용하는 대표 항목:
- 연령대, 성별, 인원수, 인종/지역
- 표정, 시선, 손동작
- 헤어, 눈, 피부, 메이크업, 체형
- 액세서리, 신발 등 직접 충돌하지 않는 외형 세부
- 분위기, 색감, 스타일, 구도, 렌즈, 질감, 효과

간단히 말하면, 겹치는 슬롯은 NSFW가 우선하고 겹치지 않는 슬롯은 일반이 계속 담당합니다.
예를 들어 NSFW 배경과 NSFW 조명을 선택한 상태에서 미선택 랜덤을 누르면, 일반 배경/일반 조명은 자동으로 밀리고 인물, 스타일, 색감, 구도 같은 일반 항목은 계속 랜덤에 참여합니다.

전체 랜덤도 같은 원칙을 따릅니다.
NSFW 탭이 닫힌 상태에서 전체 랜덤을 누르면 일반 랜덤으로 작동하고, NSFW 탭이 열린 상태에서 전체 랜덤을 누르면 NSFW 배경/조명/착의 계열이 우선되는 NSFW 랜덤으로 작동합니다.

34. 커스텀 입력 사용법
============================================================

커스텀 입력은 기존 POOL에 없는 표현을 직접 넣는 기능입니다.

커스텀 입력에는 보통 세 칸이 있습니다.

KO:
- 화면에 보이는 한글 이름

NL:
- 자연어형에 들어갈 영어 표현

TAG:
- 태그형에 들어갈 쉼표 태그

예:

KO:
검은 실크 드레스

NL:
wearing a black silk dress with elegant flowing fabric

TAG:
black silk dress, elegant dress, silk fabric

커스텀 입력은 기존 선택보다 우선적으로 반영될 수 있습니다.
너무 긴 문장을 넣으면 프롬프트가 장황해질 수 있으니 핵심만 넣는 것이 좋습니다.

35. 좋은 프롬프트를 만드는 실제 요령
============================================================

좋은 프롬프트를 만들려면 다음 원칙을 기억하세요.

1. 핵심은 직접 선택합니다.
2. 다양성은 Ctrl/⌘ 멀티선택으로 만듭니다.
3. 너무 많은 항목을 한꺼번에 고르지 않습니다.
4. 구도와 선택 항목을 맞춥니다.
5. 스타일과 품질 표현이 충돌하지 않게 합니다.
6. 배경, 시간, 날씨, 조명은 서로 어울리게 고릅니다.
7. 태그형에서는 쉼표 태그가 너무 길어지지 않게 합니다.
8. 자연어형에서는 장면과 주체를 일관된 문장으로 설명하도록 선택값을 정리합니다.

좋은 예:
- 한국인 여성 1인
- 비 오는 밤 네온 골목
- 검은 스트리트 패션
- 시네마틱 조명
- 쓰리쿼터샷
- 35mm 렌즈

나쁜 예:
- 클로즈업 얼굴 + 신발 강조 + 드론샷 + 완전한 배경 중심 + 전신 포즈

38. POOL 데이터 직접 추가 방법
============================================================

POOL은 앱의 버튼 데이터입니다.

기본 구조:

{
  ko:'한글 표시명',
  nl:[
    `영문 자연어 표현 1`,
    `영문 자연어 표현 2`,
    `영문 자연어 표현 3`
  ],
  tag:'태그형 표현'
}

예:

{
  ko:'검은 실크 드레스',
  nl:[
    `wearing a black silk dress with elegant flowing fabric`,
    `dressed in a glossy black silk dress`,
    `a refined black silk dress draping naturally over the body`
  ],
  tag:'black silk dress, elegant dress, silk fabric'
}

주의:
- 쉼표를 빠뜨리면 앱이 깨질 수 있습니다.
- 작은따옴표와 백틱을 기존 형식에 맞춰 사용하세요.
- ko는 짧고 명확하게 작성하세요.
- nl은 자연어형 문장 조각입니다.
- tag는 쉼표로 나뉘는 태그형 표현입니다.

============================================================
39. 압축 보기 카테고리에 데이터 넣기
============================================================

POOL에 항목을 추가해도 압축 보기의 원하는 카테고리에 자동으로 들어가지 않을 수 있습니다.
이때는 COMPACT_SLOT_CONFIG 쪽의 분류 규칙을 확인해야 합니다.

예:
새 의상 항목이 “레트로 데님 재킷”이라면, 캐주얼 또는 재킷 계열 정규식에 걸려야 원하는 하위 카테고리에서 보일 수 있습니다.

데이터 추가 시 확인할 것:

1. POOL에 항목이 들어갔는가
2. 전체 보기에서 보이는가
3. 대표 보기에 넣을 필요가 있는가
4. 하위 카테고리에서 보이는가
5. Ctrl/Shift 선택이 정상인가
6. 자연어형 결과에 nl이 들어가는가
7. 태그형 결과에 tag가 들어가는가

40. ITEM_BIAS 가중치 이해
============================================================

ITEM_BIAS는 랜덤에서 특정 항목이 얼마나 자주 나올지 정하는 가중치입니다.

예:

'쓰리쿼터샷': 6

숫자가 높으면 더 자주 나옵니다.
숫자가 낮으면 덜 나옵니다.

단, 너무 높은 값을 주면 특정 항목만 반복될 수 있습니다.

추천:
- 자주 나오면 좋은 기본 항목: 5~8
- 평범한 항목: 1~3
- 특수한 항목: 1

============================================================

단순 의상이나 배경은 POOL 추가만으로 충분할 수 있습니다.
하지만 아래 항목은 관련 함수도 확인해야 합니다.

- NSFW 노출 단계
- NSFW 포즈
- 배경만 모드에 영향을 주는 항목

- 충돌 방지와 관련된 항목

예:
구도에 새 항목을 추가하면 단순히 POOL.cang에 넣는 것만으로 부족할 수 있습니다.
FULLBODY_CANG, CLOSEUP_CANG, framingSemanticProfile 같은 관련 판별에도 반영해야 할 수 있습니다.

42. 문제 해결
============================================================

------------------------------------------------------------
42-1. 자연어형에서 태그형으로 바꿨는데 결과가 안 바뀌는 것처럼 보일 때
------------------------------------------------------------

공개본에서는 형식 변경 시 결과 리스트가 자동 재생성되어야 합니다.
만약 미리보기만 바뀌고 결과 리스트가 그대로라면 브라우저 캐시로 이전 파일을 열었을 수 있습니다.

해결:
- 최신 공개본 HTML을 다시 열기
- Ctrl+F5 새로고침
- 파일명이 비슷한 이전 파일을 열고 있지 않은지 확인

------------------------------------------------------------
42-2. 이미지 분석 번역 버튼이 안 보이거나 안 눌릴 때
------------------------------------------------------------

분석 결과가 있어야 번역 버튼이 활성화됩니다.
분석 결과가 비어 있으면 번역할 내용이 없습니다.

번역 레이어는 이미지 분석창 위에 표시되어야 합니다.
만약 안 보이면 브라우저 확대/축소 또는 창 위치 문제일 수 있습니다.

------------------------------------------------------------
42-3. API 키가 있는데 실패할 때
------------------------------------------------------------

가능한 원인:
- 키 오타
- 모델 권한 없음
- 모델명 변경
- API 크레딧 부족
- 안전 필터
- 네트워크 문제

해결:
- 키 다시 입력
- API 제공 사이트에서 사용 가능 여부 확인
- 모델명 확인
- 프롬프트를 단순하게 줄여보기

------------------------------------------------------------
42-4. Ollama 모델 목록이 안 뜰 때
------------------------------------------------------------

가능한 원인:
- Ollama가 실행되지 않음
- ollama serve가 실행 중이 아님
- localhost:11434 접속이 차단됨
- 브라우저 또는 보안 설정 문제

해결:
- Ollama 앱을 실행합니다.
- 필요하면 터미널에서 ollama serve를 실행합니다.
- 이미지 분석창에서 목록 새로고침을 누릅니다.
- 모델이 설치되어 있는지 확인합니다.

------------------------------------------------------------
42-5. Ollama에서 분석 결과가 너무 짧거나 부족할 때
------------------------------------------------------------

Ollama는 로컬 Vision 모델의 성능에 따라 결과 품질이 크게 달라집니다.
GPT/Gemini보다 프롬프트 재구성 능력이 약할 수 있습니다.

해결:
- 더 좋은 Vision 모델을 선택합니다.
- 커스텀 지시어에 “조명, 배경, 구도, 스타일을 더 자세히”처럼 원하는 분석 초점을 적습니다.
- 그래도 부족하면 GPT 또는 Gemini 분석을 사용합니다.

------------------------------------------------------------
42-6. Ollama가 이미지를 볼 수 없다고 할 때
------------------------------------------------------------

가능한 원인:
- 일반 텍스트 모델을 선택함
- Vision 모델이 아님
- 이미지 입력을 지원하지 않는 모델 태그를 선택함

해결:
- llava, qwen-vl, qwen3-vl, gemma3, minicpm-v, llama3.2-vision, pixtral 등 Vision 계열 모델을 사용합니다.
- 모델 목록에서 「Vision 확인됨」인지 확인하고, 「확인 불가」면 실제 분석 시도로 확인합니다.
- 일반 텍스트 모델은 이미지 분석에 사용할 수 없습니다.

------------------------------------------------------------
42-7. HTML 수정 후 앱이 안 열릴 때
------------------------------------------------------------

대부분 문법 오류입니다.

자주 발생하는 원인:
- 쉼표 누락
- 따옴표 누락
- 백틱 누락
- 괄호 누락
- 대괄호 누락
- 잘못된 한글 따옴표
- 주석 미종료

해결:
- 마지막으로 수정한 부분을 되돌립니다.
- 기존 항목 하나를 복사해서 값만 바꿉니다.
- 한 번에 여러 부분을 수정하지 않습니다.

============================================================
43. 직접 수정 후 점검 체크리스트
============================================================

소스를 직접 수정했다면 아래를 확인하세요.

기본 점검:
- HTML이 브라우저에서 열리는가
- 개발자 콘솔에 빨간 오류가 없는가
- 기본 탭이 정상 표시되는가

선택 점검:
- 항목 클릭이 되는가
- Ctrl/⌘ 멀티선택이 되는가
- Shift 전체 선택이 되는가
- 선택 요약에 표시되는가
- 남녀 혼성 클릭 시 세부 패널이 열리는가
- 우측 현재 선택 목록의 × 버튼으로 해제가 되는가

생성 점검:
- 자연어형 생성이 되는가
- 태그형 생성이 되는가
- 형식 전환 시 결과 리스트가 자동 재생성되는가
- 기본 방향·자연어 길이 변경 시 현재 출력이 맞게 반영되는가

모드 점검:
- 배경만 생성에서 인물 subject가 나오지 않는가
- NSFW ON/OFF가 정상인가
- NSFW 장소와 일반 배경/날씨/이벤트가 어색하게 섞이지 않는가
- 포즈 조합 허용 ON/OFF가 정상인가
- pose + gaze, pose + gesture가 심하게 충돌하지 않는가

이미지 기능 점검:
- 이미지 미리보기 레이어가 열리는가
- 이미지 분석 레이어가 열리는가
- 이미지 미리보기에는 OpenAI/Gemini만 표시되는가
- 이미지 분석에는 GPT/Gemini/Ollama가 표시되는가
- GPT/Gemini API 키 입력 패널이 정상인가
- Ollama 선택 시 API 키 입력 대신 모델 선택 영역이 표시되는가
- Ollama Vision 모델 목록이 표시되는가
- 이미지 업로드가 되는가
- 분석 결과가 표시되는가
- 분석 결과 복사/번역이 되는가

초기화 점검:
- 좌하단 초기화 시 선택 항목이 사라지거나 저장 설정 상태로 복원되는가
- 출력 형식/기본 방향/자연어 길이/생성 개수가 의도대로 돌아가는가
- 이미지 분석 결과가 초기화되는가
- 저장된 선택 설정은 삭제되지 않는가
- 저장된 OpenAI/Gemini API 키는 삭제되지 않는가

============================================================
44. 최종 빠른 요약
============================================================

가장 간단한 사용법:

1. 원하는 항목을 선택합니다.
2. 중요한 것은 일반 클릭으로 고정합니다.
3. 여러 후보는 Ctrl/⌘ 클릭으로 고릅니다.
4. 하위 카테고리 전체를 후보로 쓰려면 Shift 클릭합니다(접힌 항목도 포함).
5. 필요하면 남녀/그룹 세부 설정을 사용합니다.
6. 필요하면 포즈 조합 허용을 켭니다.
7. 자연어형 또는 태그형을 고릅니다.
8. 기본 방향(자동·중립/실사/일러스트·애니)과 자연어 길이(간결/표준/상세)를 정합니다.
9. 특정 화풍이 필요하면 아티스트 입력을 사용합니다.
10. 생성 개수를 정합니다.
11. 생성하기를 누릅니다.
12. 결과를 복사하거나 번역하거나 이미지 미리보기로 확인합니다.

기억할 핵심:

- 일반 클릭 = 하나 고정
- Ctrl/⌘ 클릭 = 후보 추가/해제
- Shift 클릭 = 누른 하위 카테고리 내부 항목 전체 선택/해제
- 미선택 랜덤 = 비어 있는 곳만 채움
- 전체 랜덤 = 더 넓게 다시 랜덤
- 자연어형/태그형 전환 = 기존 결과 개수만큼 자동 재생성
- 좌하단 초기화 = 현재 화면 초기화 또는 저장 설정 기준 복원, 저장 설정과 저장 API 키는 유지
- 이미지 분석 = 독립 레이어에서 업로드 이미지를 프롬프트 1개로 분석
- 이미지 미리보기 = 프롬프트로 이미지를 생성해 보는 기능
- Ollama = 이미지 분석 전용, Vision 모델 필요, 이미지 생성 불가
- GPT/Gemini = 이미지 분석과 이미지 미리보기에서 각각 API 키 필요

45. 한·영 화면 전환과 모바일·키보드 사용
============================================================

상단의 KO/EN 스위치에서 KO는 한글 UI, EN은 영문 UI입니다. 스위치는 좁은 화면에서도 사용할 수 있으며 현재 언어가 표시됩니다.
- 언어를 전환해도 POOL의 내부 선택 키, 프리셋, 고정·멀티선택, 아티스트 설정과 이미 생성된 영어 프롬프트는 바뀌지 않습니다.
- 입력칸에 직접 붙여넣은 한국어·영어·특수문자 및 이미지 분석의 원문은 사용자가 제공한 데이터이므로 임의 번역하지 않습니다.
- 영문 화면에서는 한국어로 번역하는 전용 결과 버튼이 숨겨질 수 있습니다. 생성된 영어 문장 자체는 변하지 않습니다.
- 모바일에서는 왼쪽 메뉴를 열고 닫아 선택 패널과 결과 패널을 번갈아 사용할 수 있습니다.

키보드 기본 동작:
- Tab / Shift+Tab: 포커스 이동
- Enter / Space: 일반 선택
- Ctrl+Enter / Ctrl+Space: 여러 후보 중 하나를 추가하거나 해제 (Windows/Linux)
- ⌘+Enter / ⌘+Space: 후보 추가·해제 (macOS)
- Shift+Enter / Shift+Space: 현재 하위 카테고리의 후보 일괄 선택·해제
- 이미지 분석·이미지 미리보기·아티스트 설정 창: 열면 창 안으로 포커스가 이동하고, Tab은 창 내부를 순환합니다. Esc로 닫을 수 있습니다.

키 조합은 현재 활성화된 항목과 하위 카테고리를 기준으로 작동합니다. 여러 후보를 선택하더라도 한 슬롯에서 모든 항목을 한 번에 출력하는 것이 아니라, 생성할 때 후보 중 하나를 뽑습니다.

46. Ollama Vision 이미지 분석 사용법
============================================================
Ollama Vision은 로컬 Ollama 서버에서 실행 중인 멀티모달 모델로 이미지를 분석해 영어 프롬프트를 만드는 기능입니다.

사용 전 점검:
- Ollama 앱 또는 `ollama serve`가 실행 중인지 확인합니다.
- 앱과 같은 PC의 기본 서버 주소는 `http://localhost:11434`입니다.
- 브라우저 주소창에서 `http://localhost:11434/api/tags`가 JSON으로 열리는지 확인합니다.
- Ollama 모델 목록에 실제 Vision 기능을 지원하는 모델이 설치되어 있어야 합니다.

연결 및 모델 선택:
1. 이미지 분석 창에서 「Ollama Vision」을 선택합니다.
2. 「목록 새로고침」으로 `/api/tags` 연결을 확인합니다.
3. 설치된 모델의 `/api/show` `capabilities` 값으로 Vision 지원을 확인합니다.
4. 「👁 Vision 확인됨」 모델을 선택합니다. 확인이 불가능한 경우 일부 모델은 「확인 불가·시도 가능」으로 표시됩니다.
5. 이미지를 업로드하고 필요한 경우 한국어 커스텀 지시어를 입력합니다.
6. 분석을 실행하여 영어 프롬프트를 확인합니다.

상태 구분:
- 「연결됨」: `/api/tags` 조회가 성공한 상태입니다. Vision 모델 존재 여부와는 별개입니다.
- 「Vision 확인됨」: 해당 모델의 `capabilities`에 vision이 있습니다.
- 「이미지 미지원」: 해당 모델에서 vision이 명시적으로 확인되지 않은 것이 아니라, `/api/show`가 vision 미지원을 명시한 상태입니다.
- 「확인 불가·시도 가능」: 검사하지 못했거나 응답에서 판정할 수 없는 경우입니다. 실제 분석 가능 여부는 실행해 봐야 합니다.

PC 포맷 후 CORS 오류가 나는 경우:
- `api/tags` URL이 주소창에 열려도 앱의 `fetch()` 요청은 CORS·로컬 네트워크 권한·혼합 콘텐츠로 차단될 수 있습니다.
- 브라우저 F12 → Console에서 원인을 확인합니다.
- 필요한 경우 Ollama의 `OLLAMA_ORIGINS`에 앱의 실제 출처를 추가하고 Ollama를 재시작합니다.
- `OLLAMA_ORIGINS=*`는 모든 출처를 허용합니다. 사용자가 자신의 PC에서 이 설정으로 연결을 복구한 사례가 있지만, 보안상 필요한 출처만 허용하는 편이 좋습니다. 11434 포트를 인터넷에 직접 공개하지 마세요.
- 별도 컴퓨터/서버에서 Ollama를 구동하면 앱의 `localhost`는 브라우저를 실행하는 컴퓨터를 뜻합니다. 이 경우 주소·네트워크 구성 변경이 필요합니다.

기술적 동작:
- `/api/show`는 최대 16개 모델을 우선 확인하며, 더 많은 설치 모델은 확인 불가로 남을 수 있습니다.
- `/api/chat`에는 `think: false`를 전달하며, 추론 사고문 자체를 프롬프트로 사용하지 않습니다.
- 로컬 모델 크기에 따라 분석 시간이 길어질 수 있고, 이미지 분석용으로 축소된 이미지가 전송됩니다.
- Ollama는 현재 앱에서 **이미지 분석 전용**이고 이미지 미리보기 API 공급자는 아닙니다.

47. 남녀/그룹 세부 설정 사용법
============================================================

남녀/그룹 세부 설정은 기본 subject 위에 추가되는 세부 설정입니다.
기본 연령대, 성별, 인원수, 인종/지역 구조는 그대로 유지됩니다.
그 위에 남녀별 연령, 인종/지역, 인원수를 더 자세히 지정할 수 있습니다.

사용 가능한 세부 설정:

- 여성 연령대
- 여성 인종/지역
- 여성 인원수
- 남성 연령대
- 남성 인종/지역
- 남성 인원수
- 같은 성별 소그룹 혼합

예시:

남녀 커플:
- 기본 성별: 남녀 혼성
- 기본 인원수: 커플
- 여성 연령대: 20대
- 여성 인종/지역: 한국인
- 남성 연령대: 40대
- 남성 인종/지역: 서양/유럽계

소그룹 혼성:
- 기본 성별: 남녀 혼성
- 기본 인원수: 소그룹
- 여성 인원수: 1명
- 남성 인원수: 자동으로 4명 보완 가능

같은 성별 혼합:
- 기본 성별: 여성
- 기본 인원수: 소그룹
- 여성 세부 인원수: 1명 + 4명 혼합
- 서로 다른 연령대 조합 가능

중요 규칙:
- 기본 subject가 먼저 적용됩니다.
- 세부 설정은 해당 성별이 실제로 등장할 때만 의미가 있습니다.
- 기본값과 같은 세부값은 중복 저장되지 않도록 정리될 수 있습니다.
- 남녀별 인원수는 남녀 혼성 + 소그룹에서 가장 의미가 큽니다.
- 합계가 6명 이상이 되는 잘못된 세부 인원수는 자동 정리될 수 있습니다.
- 세부 선택이 있으면 패널이 자동으로 닫히지 않아야 합니다.

하지 않는 기능:
- 여성 포즈 / 남성 포즈 분리
- 여성 의상 / 남성 의상 분리
- 여성 표정 / 남성 표정 분리
- 여성 행동 / 남성 행동 분리

이 기능은 인원·연령·지역 조합을 위한 것이며, 성별별 의상이나 포즈를 따로 고정하는 기능이 아닙니다.

48. 포즈 조합 허용 기능
============================================================

포즈 조합 허용은 하나의 기본 포즈에 보조 포즈 성격을 더해 더 다양한 장면을 만들기 위한 기능입니다.

예:
- 벽에 등을 기대고 + 정면을 바라보며 서있는
- 창가에 기대고 + 커피잔을 든 포즈
- 앉은 포즈 + 책을 읽는 동작

사용 방법:

1. 포즈 조합 허용을 켭니다.
2. 조합 후보가 표시되는지 확인합니다.
3. 기본 포즈를 직접 선택하거나 랜덤에 맡깁니다.
4. 생성 결과에서 조합 표현이 자연스러운지 확인합니다.

주의:
- 조합 허용만 켰다고 해서 특정 포즈가 직접 선택된 것은 아닙니다.
- 조합 후보와 기본 후보는 역할이 다릅니다.
- 같은 성격의 포즈끼리 무리하게 조합되지 않도록 보정됩니다.
- 자동 랜덤에서는 pose+gaze, pose+gesture 충돌이 줄어들도록 보정됩니다.
- 사용자가 직접 고른 충돌 조합은 의도일 수 있으므로 가능한 유지됩니다.

결과가 어색할 때:
- 포즈를 하나만 직접 선택합니다.
- 시선이나 손동작을 줄입니다.
- 구도를 포즈에 맞춥니다.
- 앉은 포즈는 앉은 동작/손동작과 함께 쓰는 것이 좋습니다.

49. 배경만/NSFW 자동 조합의 이해
============================================================

현재 버전에서는 배경만, NSFW, 일반 모드가 서로 섞이지 않도록 많은 보정이 들어갔습니다.
사용자는 이 보정을 자세히 몰라도 되지만, 결과가 왜 자동으로 정리되는지 이해하면 좋습니다.

배경만 모드:
- 인물 subject가 결과에 나오지 않아야 합니다.
- 인물 중심 이벤트가 자동으로 끼어들지 않아야 합니다.
- 배경, 시간, 계절, 날씨, 조명, 분위기, 스타일, 구도가 중심이 됩니다.

NSFW 모드:
- 성인 subject가 유지되어야 합니다.
- NSFW 장소가 있을 때 일반 배경/이벤트/날씨/시간이 부자연스럽게 남지 않도록 정리됩니다.
- 솔로 남성, 솔로 여성, 커플 상황에 따라 신체 detail이 잘못 남지 않도록 보정됩니다.


NSFW와 일반 항목의 우선순위:
- NSFW가 활성화되면 의상/배경/조명처럼 같은 성격으로 겹치는 항목은 NSFW 쪽이 우선합니다.
- 인물 정보, 표정, 헤어, 색감, 스타일, 구도처럼 직접 겹치지 않는 항목은 일반 쪽이 계속 사용됩니다.
- 따라서 NSFW는 일반 기능을 전부 끄는 모드가 아니라, 충돌이 큰 부분만 NSFW 전용 슬롯으로 바꾸는 확장 모드에 가깝습니다.

자동 보정의 원칙:
- 자동 랜덤끼리 충돌할 때는 앱이 정리합니다.
- 사용자가 직접 고른 값은 가능한 유지합니다.
- 직접 선택이 서로 충돌하면 사용자의 의도일 수 있으므로 무조건 삭제하지 않습니다.

예:
사용자가 직접 “비 오는 날씨”와 “실내 침실 NSFW 장소”를 함께 고르면 앱이 무조건 지우지 않을 수 있습니다.
하지만 자동 랜덤에서 그런 조합이 우연히 생기면 정리될 가능성이 큽니다.

50. 수동 미리보기·형식 전환·TXT 내보내기·랜덤 다양성
============================================================

미리보기와 결과는 서로 다른 작업 상태입니다.
- 미리보기의 「수정」에서 사용자가 직접 고친 원문은 자연어형과 태그형 각각 별도 보관합니다.
- 길이(간결/표준/상세) 또는 기본 방향(자동·중립/실사/일러스트·애니)을 바꾸더라도 해당 형식의 수동 편집본을 보존합니다.
- 자연어형에서 직접 작성한 문장을 태그형으로 전환할 때 원문을 자동 태그로 번역했다고 가정하지 마십시오. 태그형에 별도 수동 편집본이 없으면 원래 자동 생성 초안에서 태그형을 조립합니다.
- 실제 선택값·프리셋을 바꾸거나 초기화하면 현재 편집 작업의 유효 범위도 바뀔 수 있습니다. 장기간 보관할 원문은 별도로 복사해 두면 안전합니다.

TXT 내보내기:
- 생성된 각 프롬프트는 TXT 파일의 물리적 한 줄을 차지합니다.
- 사용자가 직접 입력한 줄바꿈은 파일 안에서 문자 `\n`으로, 원래 역슬래시는 `\\` 형태로 이스케이프됩니다.
- 한 줄당 한 프롬프트를 읽는 외부 도구와 함께 사용할 때 편리하지만, 원래 여러 줄 형식으로 복원하려면 이스케이프 규칙을 처리해야 합니다.
- 저장 결과 개수는 1~100개이며, 파일 안의 실제 줄 수로 결과 개수를 확인할 수 있습니다.

랜덤 다양성:

51. 범용 자연어형·태그형과 간결/표준/상세

- 상세: 표준에서 선택된 시각 요소를 기준으로 배경 깊이, 빛과 그림자, 옷감·재질, 피부 명암, 카메라 거리·시각 매체의 관찰 정보를 보강합니다. 새 인물·행동·장소를 임의로 삽입하는 설정이 아닙니다.

- 배경/분위기 디테일이 더 필요하면 「상세」를 선택하십시오.
- 아무리 상세한 문장이라도 사용 이미지 모델의 토큰 처리 방식·학습 특성에 따라 반영 결과는 달라질 수 있습니다.

52. API 키, 임시 키와 문제 해결
============================================================

OpenAI와 Gemini의 API 키는 이미지 분석과 선택적 AI 이미지 미리보기에서 공급자별로 공유됩니다. 한쪽 창에서 저장 키를 삭제하면 같은 공급자를 사용하는 다른 창에서도 더 이상 사용할 수 없으므로 삭제 안내를 확인하십시오.
- 분석창에서 「이번만 사용」으로 입력한 임시 키가 저장 키보다 우선할 수 있습니다. 실제로 적용되는 키 상태를 확인하십시오.
- Ollama Vision은 기본적으로 `http://localhost:11434` 서버의 설치 모델 목록을 사용하며, 이미지 분석을 위한 Vision 지원 모델이 필요합니다. API 키를 입력하지 않습니다.
- `/api/tags`에 접근된다고 앱 JavaScript의 호출까지 허용되는 것은 아닙니다. CORS 또는 브라우저 로컬 네트워크 권한을 확인하십시오.
- 환경에 따라 `OLLAMA_ORIGINS` 설정이 필요할 수 있습니다. `*`는 모든 출처를 허용하므로 로컬 API 포트를 외부 인터넷에 공개하지 마십시오.
- OpenAI/Gemini는 계정·프로젝트·모델에 따라 무료 할당량이 없거나 비용이 발생할 수 있습니다. API 키가 있다는 사실만으로 무료 사용을 보장하지 않습니다.
- 키 저장은 브라우저의 localStorage를 사용하므로 공용 기기·공유 출처·백업 파일과 같은 보안 상황을 고려해야 합니다.
- 이미지 분석의 오류와 실제 이미지 생성 API의 오류는 별개입니다. 공급자·모델 ID·쿼터·이미지 형식·네트워크를 각각 확인하십시오.
- 잘못된 이미지나 손상된 파일을 업로드한 경우 디코딩 오류가 나올 수 있으며, 일반 텍스트 전용 Ollama 모델은 이미지 분석에 사용할 수 없습니다.

부록 C. 자주 헷갈리는 표현 정리
============================================================
- 자연어형: 문장처럼 이어지는 영어 프롬프트입니다.
- 태그형: 쉼표로 구분된 태그 프롬프트입니다.
- POOL: 앱의 선택 버튼 데이터 묶음입니다.
- nl: 자연어형에서 사용되는 영어 문장 후보입니다. 배열이면 그중 하나가 랜덤으로 선택될 수 있습니다.
- tag: 태그형에서 사용되는 쉼표 태그 묶음입니다. 쉼표로 나뉘지만 항목 자체는 한 버튼에 연결되어 있습니다.
- 미리보기: 현재 선택 상태의 샘플 1개입니다.
- 결과 리스트: 생성하기로 만든 실제 여러 프롬프트입니다.
- 이미지 미리보기: 프롬프트를 이미지로 생성해 보는 기능입니다.
- 이미지 분석: 업로드 이미지를 읽어 영어 프롬프트 1개로 바꾸는 기능입니다.
- 좌하단 초기화: 저장된 선택 설정이 있으면 그 설정 상태로 되돌리고, 저장된 선택 설정과 저장 API 키는 삭제하지 않습니다.

부록 D. 슬롯별 세부 사용 가이드
============================================================

이 부록은 실제 사용자가 어떤 슬롯을 언제 선택하면 좋은지 설명합니다. 모든 슬롯을 매번 선택할 필요는 없습니다. 중요한 컨셉만 고르고 나머지는 비워두거나 미선택 랜덤을 사용하는 것이 좋습니다.


연령대
---
인물의 나이 인상을 정합니다. 포트레이트에서는 결과에 강하게 반영됩니다. NSFW를 사용할 때는 성인 연령대를 명확히 선택하는 것이 좋습니다.
- 18·19세 성인 연령은 원래 선택한 나이 그대로 명확히 유지하며 모호한 teens 표현으로 바꾸지 않습니다.
- 20대/30대는 일반 포트레이트에 무난
- 중년/노년층은 얼굴 주름, 분위기, 의상 선택과 함께 쓰면 좋음

성별
--
영어 문장의 woman, man, people 같은 핵심 명사를 결정합니다. 남녀 혼성이나 커플에서는 문장 구조가 달라질 수 있습니다.
- 1인 이미지는 성별 선택이 매우 중요
- 소그룹은 people 표현이 중심
- 커플은 관계성과 포즈가 같이 선택되면 좋음

인종/지역
-----
인물의 외형적 계열을 지정합니다. 한국인, 동아시아계, 유럽계, 동남아시아계 같은 표현은 모델의 얼굴 인상에 영향을 줍니다.
- 정확한 국적보다 넓은 지역 계열이 안정적일 때가 많음
- 한국인 이미지를 원하면 한국인 또는 East Asian 관련 항목을 직접 선택
- 이미지 분석에서는 확신이 낮을 때 East Asian, Southeast Asian 같은 넓은 표현을 사용

표정
--
인물의 감정과 분위기를 정합니다. 미소, 무표정, 도도한 표정, 수줍은 표정 등은 결과 인상에 크게 작용합니다.
- 표정은 2~4개 멀티선택하면 다양성이 좋음
- 강한 감정 표현은 구도와 잘 맞춰야 함
- 뷰티 포트레이트에서는 과한 표정보다 차분한 표정이 안정적

시선
--
카메라를 보는지, 옆을 보는지, 아래를 보는지 정합니다. 인물 이미지의 심리적 방향을 바꿉니다.
- 카메라 응시는 프로필/포트레이트에 좋음
- 옆을 보는 시선은 영화적 장면에 좋음
- 눈을 감은 표현은 몽환적/감성적 이미지에 좋음

포즈
--
몸의 자세를 결정합니다. 포즈는 구도와 강하게 연결됩니다.
- 전신 포즈는 전신샷 또는 풀샷과 잘 맞음
- 상반신 포즈는 상반신 포트레이트와 잘 맞음
- 복잡한 액션 포즈는 와이드 구도에서 더 잘 보임

손동작
---
손의 위치와 행동을 정합니다. 클로즈업이나 상반신에서 의미가 큽니다.
- 얼굴 근처 손동작은 뷰티 포트레이트에 좋음
- 소품을 든 손은 상황 행동과 함께 쓰면 좋음
- 전신샷에서는 손동작이 약하게 보일 수 있음

헤어 길이
-----
머리 길이를 정합니다. 얼굴형과 스타일에 큰 영향을 줍니다.
- 짧은 머리는 현대적/활동적 인상
- 긴 머리는 여성스러운 실루엣이나 판타지 이미지에 좋음
- 앞머리와 함께 선택하면 더 분명해짐

헤어 스타일
------
스트레이트, 웨이브, 묶음머리, 업스타일 같은 헤어 형태를 정합니다.
- 웨이브는 부드러운 인상
- 포니테일은 활동적 인상
- 업스타일은 포멀/고급 이미지에 좋음

헤어 색상
-----
검정, 브라운, 금발, 컬러 헤어 등 색을 정합니다.
- 실사 한국인/동아시아계는 검정/다크브라운이 안정적
- 애니/일러스트는 컬러 헤어도 잘 어울림
- 너무 많은 색상 요소와 충돌하지 않게 주의

피부
--
피부 톤과 질감을 정합니다. 포트레이트에서 중요합니다.
- 클로즈업은 피부 디테일이 잘 반영됨
- 전신샷은 피부 표현보다 전체 실루엣이 우선
- 메이크업과 함께 쓰면 더 정돈된 결과가 나옴

메이크업
----
얼굴의 화장 스타일을 정합니다.
- 내추럴 메이크업은 대부분의 포트레이트에 무난
- 스모키 메이크업은 강한 분위기와 잘 맞음
- 글로시 립은 뷰티 포트레이트에 좋음

의상
--
이미지의 캐릭터성과 분위기를 크게 결정합니다.
- 패션 이미지에서는 반드시 선택 추천
- 상반신 구도에서는 상의 중심 의상이 잘 보임
- 전신샷에서는 신발과 하의까지 의미가 커짐

신발
--
전신샷이나 풀샷에서 중요합니다.
- 클로즈업에서는 거의 반영되지 않을 수 있음
- 패션 전신샷에서는 신발이 이미지 완성도를 높임
- 의상과 색감이 어울리게 선택

액세서리
----
작은 장식 요소입니다. 포트레이트의 디테일을 살립니다.
- 귀걸이, 목걸이, 안경은 얼굴 중심 구도에서 잘 보임
- 가방, 모자, 장갑은 패션/상황 이미지에 좋음
- 너무 많이 고르면 프롬프트가 산만해질 수 있음

배경
--
장면의 장소를 정합니다. 인물보다 배경이 중요하면 배경 관련 항목을 더 많이 선택하세요.
- 카페/거리/호텔은 실사 인물에 좋음
- 숲/해변/산은 자연광과 잘 맞음
- 미래 도시/폐허/판타지는 강한 스타일과 잘 맞음

시간대
---
아침, 낮, 해질녘, 밤 같은 시간 느낌입니다.
- 골든아워는 따뜻한 포트레이트에 좋음
- 밤은 네온/플래시/저조도와 잘 맞음
- 아침은 깨끗하고 부드러운 이미지에 좋음

날씨
--
비, 눈, 안개 등 분위기를 크게 바꿉니다.
- 비는 네온과 반사 효과에 좋음
- 안개는 몽환/판타지에 좋음
- 눈은 겨울 의상과 잘 맞음

조명
--
사진/이미지의 품질을 결정하는 핵심 요소입니다.
- 소프트박스는 뷰티 포트레이트에 좋음
- 네온은 도시 야경에 좋음
- 플래시는 강한 피사체 분리에 좋음

색감
--
전체 컬러 팔레트와 후처리 느낌입니다.
- 블루/마젠타는 네온 도시와 잘 맞음
- 골든톤은 따뜻한 감성에 좋음
- 모노톤은 고급/차분한 이미지에 좋음

스타일
---
사진, 애니, 일러스트, 수채화, 유화, 3D 등 매체를 결정합니다.
- 스타일은 다른 품질 표현보다 우선되는 경우가 많음
- 수채화에는 부드러운 번짐과 색감 표현이 좋음
- 사진 계열에는 렌즈와 조명을 함께 선택하면 좋음

구도
--
무엇이 얼마나 보이는지 결정합니다.
- 얼굴 중심은 클로즈업/헤드샷
- 패션은 쓰리쿼터샷/전신샷
- 배경은 와이드 환경 롱샷

렌즈
--
사진적 거리감과 배경 흐림을 정합니다.
- 85mm는 포트레이트
- 35mm는 거리/환경 인물
- 24mm는 공간감 있는 장면
- f/1.4는 얕은 심도

부록 F. 오류와 혼동을 줄이는 사용 습관
============================================================

1. 중요한 항목은 직접 선택하세요.
랜덤에 맡기면 원하는 항목이 항상 나오지 않을 수 있습니다.

2. 결과가 이상하면 선택 요약을 먼저 확인하세요.
생각보다 많은 항목이 선택되어 충돌하고 있을 수 있습니다.

3. 자연어형/태그형을 바꾼 뒤 결과 리스트가 자동 재생성되는지 확인하세요.
공개본은 전환 시 기존 결과 개수만큼 다시 생성됩니다.

4. 좌하단 초기화는 저장된 선택 설정이 있으면 그 상태로 복원하고, 저장된 선택 설정이 없을 때만 공개본 기본값으로 정리합니다.
저장된 선택 설정과 저장된 API 키는 삭제되지 않습니다.

5. API 키를 소스에 넣은 파일은 절대 공유하지 마세요.
하드코딩 키는 편리하지만 보안 위험이 큽니다.

6. 이미지 분석은 분석 도구입니다.
메인 POOL과 자동으로 섞이지 않습니다. 분석 결과는 복사해서 사용하세요.

7. 커스텀 지시어는 변형 지시가 아니라 분석 우선순위 지시에 가깝게 쓰세요.
예: “조명과 배경 중심으로 분석”은 좋습니다. “완전히 다른 옷으로 바꿔줘”는 분석 목적과 맞지 않습니다.

부록 G. NSFW 사용 시 추가 주의
============================================================

NSFW 탭은 성인용 이미지 프롬프트를 위한 기능입니다. 성인 인물 중심의 프롬프트로 사용하세요.

좋은 흐름:
1. 성인 연령대 선택
2. 성별/인원수 선택
3. NSFW 착의 또는 노출 단계 선택
4. NSFW 배경과 조명 선택
5. 구도를 선택
6. 결과를 확인하며 충돌 표현이 없는지 확인

피해야 할 흐름:
- 어린 나이 표현과 NSFW를 함께 선택
- 미성년으로 명시된 인물과 성인 NSFW를 결합
- 완전 누드와 두꺼운 일반 의상을 동시에 강하게 선택
- 후면 포즈를 선택하고 클로즈업 헤드샷을 선택
- 예술 누드와 노골적 행위 표현을 무리하게 섞기

NSFW는 프롬프트의 민감도가 높기 때문에 결과가 모델에서 거절되거나 약화될 수 있습니다.
외부 이미지 생성·분석 모델마다 자체 이용 정책과 안전 필터가 있으므로 API 호출이 실패할 수 있습니다. 앱의 성인용 텍스트 선택·조합 기능을 임의로 축소한다는 뜻은 아닙니다.

부록 H. 이미지 분석 결과를 더 좋게 만드는 팁
============================================================

이미지 분석은 업로드 이미지의 시각 요소를 읽어 영어 프롬프트로 정리합니다. 좋은 분석 결과를 얻으려면 이미지와 지시어를 잘 준비하는 것이 좋습니다.

좋은 이미지:
- 피사체가 너무 작지 않음
- 조명과 배경이 어느 정도 보임
- 워터마크나 UI 요소가 많지 않음
- 스타일이 분명함

분석 지시어 예시:
- 조명, 배경, 색감을 자세히 분석해줘.
- 의상과 소재감을 중심으로 분석해줘.
- 사진인지 일러스트인지 스타일을 명확히 표현해줘.
- 인물 외형은 원본에 충실하게 유지하고, 분위기를 자세히 묘사해줘.

피하면 좋은 지시어:
- 완전히 다른 스타일로 바꿔줘.
- 배경을 다른 장소로 바꿔줘.
- 인물을 다른 인종으로 바꿔줘.

이런 지시어는 분석이 아니라 편집/변형에 가까우므로 이미지 분석 기능의 목적과 맞지 않습니다.


============================================================
부록 I. 항목 선택 전략 상세 설명
============================================================

이 앱은 단순히 버튼을 많이 누른다고 좋은 결과가 나오는 구조가 아닙니다. 좋은 결과는 “무엇을 고정하고, 무엇을 랜덤으로 둘지”를 잘 정하는 데서 나옵니다.

가장 중요한 기준은 다음과 같습니다.

1. 이미지의 주제를 고정합니다.
예를 들어 한국인 여성 포트레이트를 만들고 싶다면 성별, 인종/지역, 인원수는 직접 선택하는 것이 좋습니다.

2. 이미지의 분위기를 고정합니다.
시네마틱인지, 수채화인지, 애니인지, 실사 사진인지 같은 스타일은 결과 전체를 바꾸므로 직접 선택하는 것이 좋습니다.

3. 변화를 보고 싶은 요소만 랜덤으로 둡니다.
표정, 의상, 배경 후보, 색감 정도를 Ctrl/⌘로 여러 개 선택하면 결과가 다양하면서도 통제됩니다.

4. 구도는 가능하면 직접 선택합니다.
구도는 이미지의 보이는 범위를 결정하므로 랜덤으로 두면 결과가 크게 흔들릴 수 있습니다. 특히 패션, 신발, 전신 포즈를 원한다면 전신샷 또는 쓰리쿼터샷을 직접 선택하세요.

5. 배경과 날씨, 시간대는 서로 맞추는 것이 좋습니다.
밤 네온 골목을 선택했는데 밝은 한낮 자연광을 같이 강하게 선택하면 프롬프트가 충돌할 수 있습니다.

6. 스타일과 품질 표현도 서로 맞아야 합니다.
수채화 스타일에는 부드러운 번짐, 종이 질감, 색 번짐이 잘 맞습니다. 반대로 crisp photo realism 같은 표현은 수채화와 충돌할 수 있습니다.

--------

부록 L. 이미지 미리보기와 이미지 분석의 차이를 다시 정리
============================================================

이미지 미리보기와 이미지 분석은 이름이 비슷하지만 완전히 반대 방향의 기능입니다.

이미지 미리보기:
- 입력: 텍스트 프롬프트
- 출력: 이미지
- 목적: 현재 프롬프트가 어떤 이미지로 나올지 확인
- 사용하는 모델: gpt-image-2, gemini-3.1-flash-lite-image
- Ollama는 이미지 미리보기/이미지 생성 모델로 사용하지 않습니다.

이미지 분석:
- 입력: 이미지
- 출력: 텍스트 프롬프트
- 목적: 업로드한 이미지를 설명하는 영어 프롬프트 생성
- 사용하는 모델: gpt-5.4-mini, gemini-3.1-flash-lite, Ollama Vision
- Ollama는 API 키가 필요 없지만 로컬 실행과 Vision 모델이 필요합니다.

따라서 이미지 미리보기 모델과 이미지 분석 모델은 서로 다릅니다.
이미지 분석 모델을 이미지 미리보기 모델로 바꾸거나, 이미지 미리보기 모델을 분석용으로 쓰는 것은 맞지 않습니다.

이미지 분석 결과는 메인 POOL 선택값과 자동으로 합쳐지지 않습니다.
이렇게 분리한 이유는 POOL 구조가 복잡하고, 분석 결과를 자동으로 POOL에 매핑하면 오탐이나 충돌이 생기기 쉽기 때문입니다.

부록 M. API 키 관리 상세 주의사항
============================================================

API 키는 돈이 연결될 수 있는 민감한 정보입니다. 앱을 혼자 쓰는 개인용 HTML이라면 하드코딩이 편할 수 있지만, 공유 파일에는 절대 넣으면 안 됩니다.

안전한 사용 원칙:
1. 배포용 파일의 hardcodedApiKey는 반드시 빈 값이어야 합니다.
2. 다른 사람에게 HTML을 보낼 때는 API 키가 들어 있는지 다시 확인하세요.
3. GitHub, 블로그, 커뮤니티, 클라우드 공유 링크에 키가 들어간 파일을 올리지 마세요.
4. 공용 PC에서는 API 키를 localStorage에 저장하지 마세요.
5. 키가 노출되었다고 생각되면 즉시 API 제공 사이트에서 키를 폐기하고 새 키를 만드세요.

하드코딩 키와 저장 키의 차이:
- 하드코딩 키는 HTML 소스 안에 들어갑니다.
- 저장 키는 브라우저 localStorage에 저장됩니다.
- 하드코딩 키가 있으면 보통 그 키가 우선 사용됩니다.

좌하단 초기화는 저장된 API 키를 삭제하지 않습니다.
이미지 분석 초기화도 저장된 API 키를 삭제하지 않습니다.
API 키를 삭제하려면 각 레이어의 키 삭제 기능을 사용하거나, 소스의 hardcodedApiKey를 직접 비워야 합니다.

부록 N. 저장 설정과 초기화의 차이 상세 설명
============================================================

이 앱에는 비슷해 보이는 초기화 기능이 여러 개 있습니다. 헷갈리지 않도록 정확히 구분하세요.

좌하단 초기화:
- 현재 화면의 작업 상태를 기본값 또는 저장 설정 상태로 되돌립니다.
- 모델, 출력 형식, 생성 개수도 기본값 또는 저장 설정 상태로 돌아갑니다.
- 아티스트 입력 상태는 좌하단 초기화로 삭제하지 않습니다.
- 이미지 분석 상태도 초기화됩니다.
- 저장된 선택 설정은 삭제하지 않습니다.
- 저장된 API 키도 삭제하지 않습니다.

설정 저장:
- 현재 선택 상태를 브라우저에 저장합니다.
- 아티스트 입력 상태도 함께 저장됩니다.
- 저장된 설정은 다음 실행 때 자동 복원됩니다.

설정 초기화 또는 저장 설정 삭제:
- 저장된 선택 설정 자체를 삭제합니다.
- 저장 설정에 포함된 아티스트 입력 상태도 삭제됩니다.
- 이 기능은 좌하단 초기화와 다릅니다.

실제 사용 예:
1. 마음에 드는 기본 세팅을 만든다.
2. 설정 저장을 누른다.
3. 여러 실험을 한다.
4. 좌하단 초기화를 누른다. 저장된 선택 설정이 있으면 그 설정 상태로 복원되고, 저장 설정은 삭제되지 않는다.
5. 저장 설정은 삭제되지 않았으므로, 다음 실행 또는 새로고침 때 다시 자동 복원될 수 있다.

부록 P. 프롬프트 결과를 읽는 방법
============================================================

생성된 프롬프트를 볼 때는 다음 순서로 확인하면 좋습니다.

1. 주체가 맞는가?
예: woman, man, people, no humans, scenery 등

2. 나이와 인종/지역 표현이 맞는가?
예: young adult Korean woman, East Asian woman, European man 등

3. 의상이 맞는가?
의상이 너무 많이 섞이거나 노출 단계와 충돌하지 않는지 봅니다.

4. 배경이 맞는가?
배경, 시간대, 날씨, 조명이 서로 어울리는지 봅니다.

5. 스타일이 맞는가?
사진인데 수채화 표현이 섞였거나, 수채화인데 crisp photo realism이 과하게 들어가면 조정이 필요합니다.

6. 구도가 맞는가?
신발을 강조했는데 클로즈업이면 잘 보이지 않을 수 있습니다.

7. 태그형이면 태그가 너무 중복되지 않는지 봅니다.
중복 태그가 많으면 결과가 지저분해질 수 있습니다.

부록 Q. 선택 고정·계절·장면 조합을 확인하는 방법
============================================================

[선택 없이 생성하기]
아무 항목도 선택하지 않은 상태에서 「생성하기」를 누르면 결과를 만들지 않습니다.
먼저 항목 하나 이상을 선택하거나 「전체 랜덤」을 실행한 다음 생성하십시오.
모든 사용 가능한 항목을 직접 고정한 경우에는 같은 문장이 반복될 수 있습니다.

[계절과 다른 장면 요소의 관계]
일반 장면에서 봄·여름·가을·겨울을 직접 선택한 경우, 자동으로 뽑힌 배경·시간·날씨·분위기 중
명백하게 다른 계절을 명시하는 표현은 일부 교정됩니다. 예를 들어 겨울 고정과 자동으로 뽑힌
초여름 시간대가 함께 나오지 않도록 조정합니다. 직접 고른 계절·배경·시간·날씨·의상 등은
임의로 바꾸지 않습니다. 계절별 의상이나 소품을 일괄 금지하는 기능도 아닙니다.
커스텀 장면과 성인 NSFW 문맥의 직접 선택은 기존과 같이 사용자의 설정을 우선합니다.

[인물·포즈·장면 표현]
픽시컷·보브컷처럼 머리 길이 선택에 포함된 고유 헤어스타일은 가능한 경우 자연어형에서도
표현됩니다. 다른 독립 헤어스타일과 충돌할 수 있는 조합은 사용자가 결과를 검토해 주세요.
의자·소파에 앉는 복수 인물 장면이 선택되면 자동 기본 서기 자세와 충돌하지 않도록 합니다.
단, 사용자가 직접 선택한 서로 다른 포즈를 앱이 조용히 삭제하지는 않습니다.

[AI 이미지 분석의 거절 응답]
OpenAI·Gemini·Ollama가 분석 요청을 거절하거나 안전상 차단한 것으로 판정되는 응답은
영어 이미지 프롬프트로 받아들이지 않습니다. 명확한 거절 문장 대신 이미지 설명이 반환됐는지
확인해야 하며, 분석 모델의 허용 범위나 서버 측 상태는 앱이 변경할 수 없습니다.

[출력 확인]
자연어형과 TAG형은 출력 방식이 다르므로 표현이 항상 문자 그대로 같지는 않습니다.
특히 카메라 문장, 인물 수, 머리 모양, 계절·시간·배경의 관계를 함께 확인하면 좋습니다.
